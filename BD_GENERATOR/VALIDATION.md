# Alpha 0.9 검증 기록

검증일: 2026년 10월 1일

## 자동시험

합성 DOCX 및 Alpha 0.4 형식 패키지로 10개 시험을 통과했습니다.
5열·가로 용지·반복 제목·사유 공란·빨간 취소선/파란 밑줄·병합/중첩표 보존,
검토 저장/복원·병합/제외, 누락 이미지 텍스트 대체, 패키지 경로/해시/위치/스키마 오류 거부,
변경 ID 누락/중복 거부, 취소 시 기존 출력 보존을 확인했습니다.
추가·삭제 항목, 검토 저장 시 패키지 덮어쓰기 거부, 표 이미지 관계 재연결 및 각주 원문 보존도 확인했습니다.

## 실제 패키지

실제 변분기 Alpha 0.4 결과의 21개 항목(일반 문단 17개, 표 4개)을 모두 생성했습니다.
편집 가능한 대비표는 제목 1행과 변경 21행의 5열 구조이며 모든 변경 사유 셀이 공란입니다.
표 변경 블록 4개 모두 원문 표 구조를 보존했습니다. 대형 표의 각주 7개는 양쪽 표 아래에 각각 텍스트로 옮겼습니다.
이 방식에는 확인사항 19개, 이미지 방식에는 확인사항 22개가 기록되었습니다. 패키지에서 온 경고도 포함한 수치입니다.

설치된 Microsoft Word로 두 출력 파일을 읽기 전용으로 열고 PDF를 생성했습니다.
편집 가능한 방식은 17페이지, 이미지 방식은 26페이지로 정상 출력되었습니다.
편집 가능한 최종 문서의 전체 17페이지 PNG를 직접 확인하여 가로 용지, 반복 제목, 표의 페이지 연결,
변경 표시, 사유 공란 및 각주 텍스트를 검토했습니다. 이미지 방식은 전체 페이지 미리보기와 정상 열기를 확인했습니다.
기본 `render_docx.py`는 이 PC에 LibreOffice가 없어 실패했으므로 기존 변분기의 pywin32와 설치된 Word를 검증용으로만 사용했습니다.
검증용 PDF·PNG 및 업무 DOCX는 배포 ZIP이나 GitHub 업로드에 포함하지 않습니다.

큰 표를 자동으로 발췌하지 않아 문서가 길어질 수 있습니다. 좁아진 셀에서는 숫자·영문도 여러 줄로 표시될 수 있습니다.
원문 표의 각주 번호는 XML ID이므로 Word 표시 번호와 다를 수 있습니다. 원문과 확인하십시오.
일반 문단 서식·자동번호·개체는 편집 가능한 텍스트 방식에서 재현되지 않습니다.
변분기가 경고한 전후 대응과 본문 범위 차이를 이 단계에서 자동으로 교정하지 않습니다.
GUI의 모든 버튼에 대한 수동 클릭 시험이나 다양한 업무 문서에 대한 성능 검증은 수행하지 않았습니다.

## GitHub 및 배포

`UPLOAD_TO_GITHUB.ps1 -PrepareOnly`로 독립 업로드 사본의 생성, 기존 이력 복원,
`BD_GENERATOR/` 아래 소스·시험·설명서 15개만 스테이징되는 것을 확인했습니다.
이 검증에서는 커밋·네트워크 접속·실제 GitHub push를 수행하지 않았습니다.
배포 ZIP은 명시한 파일 15개와 기존 소스 이력 bundle 1개만 포함합니다.
