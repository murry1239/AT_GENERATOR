# 변대생기 Alpha 1.0

변분기 Alpha 1.0의 `.bdsg` 결과물을 읽어 문서 앞부분의 표·문단과 본문 변경을 5열 Word 변경대비표로 만드는 **2단계 프로그램**입니다.
Alpha 0.7·0.8의 출력 규칙과 검토 기능을 이어받고, 변경이력 DOCX의 승인·거부 과정은 변대생기에서 수행하지 않습니다.

## 설치와 실행

1. 통합 배포 ZIP을 새 폴더에 풉니다. `변분기_Alpha_1.0`과 `변대생기_Alpha_1.0` 두 폴더가 나옵니다. Windows 10/11, Python 3.11 이상이 필요합니다.
2. 처음 사용할 때 각 프로그램 폴더에서 `INSTALL.bat`을 한 번 실행합니다. 최초 설치 시 패키지 다운로드에 인터넷이 필요합니다.
3. 변분기 폴더의 `RUN.bat`으로 전후 DOCX를 분석한 뒤 변대생기 폴더의 `RUN.bat`을 실행합니다. 종료·재부팅 후에는 각 폴더의 `RUN.bat`만 실행하면 됩니다.
4. **.bdsg 선택**에서 변분기 Alpha 1.0 결과를 선택합니다.
5. 원문과 확인사항을 검토합니다. 더블클릭으로 Section·page를 수정할 수 있습니다.
6. 필요하면 연속 항목을 **선택 병합**하거나 **포함/제외**합니다. **검토 저장**으로 수정 사항을 별도 JSON에 저장합니다.
7. 출력 방식을 선택하고 **변경대비표 생성**을 눌러 DOCX로 저장합니다.

변분기 결과 중 `이름.bdsg`가 필요합니다. 미리보기 XLSX만으로는 전체 원문·위치·해시를 복원할 수 없어 입력으로 사용하지 않습니다.
원본 DOCX와 이미지는 패키지에 들어 있으므로 별도 파일 선택이 필요 없습니다. 미리보기 XLSX를 수정해도 대비표에는 반영되지 않습니다.
Alpha 1.0·0.5의 schema_version 3과 기존 Alpha 0.4의 schema_version 2를 지원합니다. Alpha 0.3 이전 패키지·변경이력 DOCX 직접 입력은 지원하지 않습니다.
기존 0.4 패키지에는 문서 앞부분의 변경이 없으므로 이를 포함하려면 원본 전후 DOCX를 변분기 1.0으로 다시 분석해야 합니다. 이전 패키지를 읽으면 이 안내를 표시합니다. Alpha 0.5 패키지는 재분석 없이 그대로 사용할 수 있습니다.
목차·별첨·부록 제외 범위는 변분기에서 결정합니다. 변대생기는 패키지에 포함된 변경 항목만 출력합니다.

## 출력 규칙

- 문서명만 상단에 표시합니다.
- A4 가로, `Section / page / 변경 전 / 변경 후 / 변경 사유` 5열, 반복 제목 행입니다.
- **변경 사유는 모든 행에서 공란**입니다.
- 전후 페이지는 변분기가 계산한 물리 페이지 값을 사용합니다. Word를 다시 열어 페이지를 계산하지 않습니다.
- 패키지의 변경 ID를 유지합니다. 자동으로 Section 전체를 합치거나 변경을 새로 탐지하지 않습니다.
- 병합 시 선택된 변경 블록만 차례로 삽입합니다. 사이에 있던 미변경 내용은 추가하지 않습니다.
- 취소·실패 시 기존 출력 파일을 보존합니다. 패키지·원본은 수정하지 않습니다.
- 패키지 경고와 생성 중 대체 내역은 최종 문서의 **확인사항**에 기록합니다.

### 편집 가능한 텍스트·표 기본 방식

일반 문단은 패키지의 전체 전후 텍스트를 비교해 삭제를 빨간 취소선, 추가를 파란 밑줄로 표시합니다. 일반 내용은 8pt입니다.
표는 패키지에 들어 있는 원본 DOCX의 블록을 읽어 병합·중첩표 구조와 일반 삽입 이미지를 보존하며 7pt로 작성합니다.
표의 전후 텍스트를 비교해 같은 색상 규칙을 적용합니다. 표 너비는 대비표 셀에 맞춥니다.

정확한 내용 보존을 우선하여 큰 표를 자동 발췌하거나 800자로 자르지 않습니다. 여러 페이지 표도 행 분할을 허용합니다.
원본 문단의 서식·자동번호·필드·각주·텍스트 상자·도형은 일반 문단 텍스트 출력에 재현되지 않습니다.
표 안의 각주·미주는 표 아래에 텍스트로 보존하며 원본 XML ID로 표시합니다. Word의 표시 번호와 다를 수 있어 확인사항에 기록합니다.
특수 개체·필드·콘텐츠 컨트롤을 포함한 표는 원문 텍스트로 대체하고 확인사항을 남깁니다.
그림·개체·수식이 있는 일반 문단은 확인사항에 기록하므로 이미지 방식과 원문을 함께 확인하십시오.
표 셀의 추가·삭제·병합 등 **구조 변화 자체에는 빨강/파랑 표시를 적용하지 않습니다**. 양쪽 표 구조를 직접 비교하십시오.
변분기에서 자동번호·서식만의 차이를 제외한 항목은 이 단계에서도 추가하지 않습니다.

### 패키지 이미지 방식

변분기가 이미 생성한 좌우 이미지를 사용합니다. 원문 모양을 확인하기 위한 방식이며 셀 안의 이미지 내용은 편집할 수 없습니다.
이미지의 크기는 가로세로 비율을 유지해 최대 가로 9cm·세로 15.5cm로 줄입니다. 큰 이미지는 작게 보일 수 있습니다.
캡처 실패·누락·다중 페이지 블록은 **전체 원문 텍스트**로 대체하고 확인사항에 기록합니다.
이미지는 변분기의 깨끗한 전후 캡처이므로 빨간 취소선·파란 밑줄을 추가하지 않습니다. 텍스트 대체 부분에는 변경 표시가 적용됩니다.

## 검토 저장과 복원

검토 JSON에는 패키지 SHA-256, 변경 ID 목록, Section·page 수정, 병합·제외 정보가 들어갑니다.
같은 패키지에서만 불러올 수 있으며 변경 ID 누락·중복을 거부합니다. `검토 초기화`로 원래 항목 목록을 복원할 수 있습니다.
검토 JSON에도 업무 문서 제목이 포함될 수 있으므로 업무 자료로 보관하십시오.
로그 위치는 `%LOCALAPPDATA%\변대생기\logs`이며 화면에서 **로그 열기**로 확인할 수 있습니다.
작업은 별도 스레드에서 진행합니다. 취소는 항목·좌우 셀 처리 사이에 적용되며 긴 단일 XML 비교·저장 호출은 끝날 때까지 기다립니다.

## 필요 환경

이 단계의 생성 엔진에는 Microsoft Word 설치나 COM 자동화가 필요 없습니다. 결과를 확인·편집하려면 Word 또는 DOCX 뷰어를 사용하십시오.
변분기 Alpha 1.0의 분석·캡처 단계에는 기존과 같이 Word가 필요합니다.
실행 중 문서 내용은 외부 AI나 서버로 전송하지 않습니다.

## GitHub 업로드

`UPLOAD_TO_GITHUB.bat`을 실행합니다. Git for Windows, GitHub 로그인 및 저장소 쓰기 권한이 필요합니다.
기본 저장소는 기존 변분기와 같은 `https://github.com/murry1239/AT_GENERATOR.git`입니다. 다른 저장소를 지정할 때는 PowerShell의 `-RepositoryUrl` 인수를 사용합니다.

두 프로그램을 같은 상위 폴더에 둔 통합 배포 구조에서 업로드합니다. 업로드 사본을 `.github-upload`에 준비하고
`변분기_Alpha_1.0/`과 `변대생기_Alpha_1.0/`의 소스·시험·설명서 및 `AT_GENERATOR_Alpha_1.0.zip`을 같은 커밋으로 올립니다. 작업 브랜치는 `codex/alpha-1.0`이며 이후 변경을 main에 반영할 때는 Pull Request를 사용합니다.
기존 저장소 코드와 이력은 유지합니다. 표시된 주소와 파일 목록을 확인하고 `UPLOAD`을 입력하면 커밋·push합니다.
작성자 이름·이메일이 없으면 입력을 요청하며 업로드 사본에만 설정합니다. 이메일은 커밋 이력에 공개될 수 있습니다.
업무 DOCX·BDSG·XLSX·이미지·검토 JSON·로그·가상환경은 업로드 대상에서 제외합니다.

검토용 준비만 실행하려면 다음 명령을 사용합니다. `.github-preview`에 두 폴더와 통합 ZIP을 준비하며 네트워크·커밋·push는 수행하지 않습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\UPLOAD_TO_GITHUB.ps1 -PrepareOnly
```

코드 수정은 원래 배포 폴더에서 하십시오. `.github-upload`는 업로드용 사본입니다.

## 개발과 검증

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe app.py --input "분석.bdsg" --output "변경대비표.docx"
.venv\Scripts\python.exe app.py --input "분석.bdsg" --output "이미지대비표.docx" --mode images
.venv\Scripts\python.exe tools\build_release.py
```

CLI에 `--review "검토.json"`을 더하면 저장한 검토를 적용합니다.
검증 기록은 `VALIDATION.md`, 변경 이력은 `CHANGELOG.md`에 있습니다.
정확한 전후 대응·범위·표 구조·문단 분할·페이지는 최종 작성자가 원문과 비교하여 확인하십시오.
