# AT_GENERATOR · 변분기 Alpha 1.1

변경 전·후 DOCX를 비교하여 Word에서 보이는 변경 영역을 Excel에 좌우로 배치합니다.
변경이력 DOCX는 선택 입력입니다. PDF 변환이나 외부 AI 전송은 하지 않습니다.

## 설치와 실행

1. 통합 배포 ZIP을 새 위치에 풀고 `변분기_Alpha_1.1` 폴더를 엽니다. 분석 후 최종 대비표를 작성할 때는 함께 배포된 `변대생기_Alpha_1.1`을 사용합니다. GitHub에서 받는 경우 저장소의 **Code → Download ZIP**을 누른 뒤 해당 폴더를 사용합니다.
2. Windows에 Microsoft Word 데스크톱 버전과 Python 3.11 이상을 설치합니다.
3. `INSTALL.bat`을 실행합니다. 필요한 Python 패키지는 인터넷으로 설치됩니다.
4. `RUN.bat`을 실행합니다.
5. **변경 전**, **변경 후** 파일을 선택합니다. 변경기록이 남은 파일은 **이력 선택**에 지정합니다.
6. 출력 `.bdsg` 경로를 정하고 **변경 분석 및 미리보기 생성**을 누릅니다.

업데이트를 새 폴더에 받았다면 INSTALL.bat을 다시 실행합니다. 단순 재부팅 후에는 RUN.bat만 실행합니다.
그림은 Word 범위의 EMF 데이터를 직접 받아 PNG로 변환합니다. 직접 추출 실패 시에만 클립보드로 한 번 대체하므로, 실행 중 다른 복사 작업은 피해주세요.

## Alpha 1.1

앞부분의 첨부자료 목록이 실제 별첨 시작으로 판정되어 본문 전체가 비교 범위에서 빠지는 문제를 수정했습니다. 목차 앞의 양식·표·문단과 목차 뒤의 본문을 함께 비교하고, 목차와 실제 별첨·부록 영역은 제외합니다. 앞부분 목차들 사이에 있는 일반 문단 형식의 번호가 붙은 첨부자료 목록은 앞부분으로 인식하여 비교 범위에 보존합니다.

Alpha 0.5 또는 1.0에서 본문이 빠진 결과는 원래의 **변경 전·후 DOCX를 이 버전으로 다시 분석**해야 합니다. 분석 결과 옆에 저장된 `_변경전_전체.docx`, `_변경후_전체.docx` 원본 사본도 사용할 수 있습니다. 기존 `.bdsg`를 변대생기에서 다시 여는 것만으로는 누락된 변경이 복구되지 않습니다.

새 `.bdsg`는 변대생기 Alpha 1.1에서 바로 열어 최종 DOCX 변경대비표를 작성할 수 있습니다. 기존 변대생기 Alpha 1.0과의 호환성도 유지합니다. 기존 버전을 삭제할 필요는 없습니다.

## 비교 및 분석 기능

- 목차 앞의 표지·문서정보·승인 양식 등 표와 문단도 비교합니다.
- Word 목차 필드·목차 스타일·목차 콘텐츠 컨트롤 및 제목과 페이지 번호가 있는 수동 목차를 제외합니다. 표·그림 목차의 영어 제목은 단수와 복수 형식을 모두 인식합니다.
- 실제 별첨·부록·붙임·첨부·Appendix·Annex 시작 이후를 제외합니다. 앞부분 첨부자료 목록과 표 안의 참조 문구는 본문을 종료하는 경계로 사용하지 않습니다.
- 분석 패키지는 schema_version 3이며 기존 비교 정책을 유지합니다. 새 패키지는 변대생기 Alpha 1.1 또는 1.0에서 사용합니다.
- 문단 스타일·수준·글자 서식·텍스트 run 분할만 달라진 블록은 제외합니다.
- 빈 문단·공백/쪽 나누기만 있는 문단의 추가/삭제도 간격 변경으로 보아 제외합니다. 글자가 없더라도 그림·수식·필드가 있는 문단은 유지합니다.
- 스타일/번호/테마/페이지 설정 파일이 달라도 본문 전체를 캡처하지 않습니다.
- 글자·공백·줄바꿈·표 셀 구조/병합·그림 내용·링크·수식 등의 변경은 비교 대상으로 유지합니다.
- 그림 직접 추출 실패 시 대체 경로를 사용하며, 전/후 문서 각각 연속 3회 실패하면 남은 그림 추출을 중단하고 원문 텍스트를 보존합니다. 개별 Word 호출 자체가 멈추는 현상에 대한 강제 시간 제한은 아닙니다.
- `analysis.json`에 비교 정책, 그림 추출 방식 및 성공/실패/생략 통계를 기록합니다.
- 실제 자료 시험 결과와 제한은 `VALIDATION.md`를 참고하십시오.

## 입력 원칙

| 입력 | 필수 여부 | 사용 방식 |
|---|---|---|
| 변경 전 DOCX | 필수 | 비교 기준 원문 및 이미지 |
| 변경 후 DOCX | 필수 | 비교 대상 원문 및 이미지 |
| 변경이력 DOCX | 선택 | 전후 텍스트 일치 확인 및 변경기록 보조 보관 |

변경 전·후에는 미처리 변경기록이 없어야 합니다. 파일명이 달라도 같은 파일을 중복 선택할 수 없습니다.
전체 승인/거부로 전후 복원본을 만드는 과정을 생략합니다. 원본은 저장하거나 수정하지 않습니다.
이미지용 임시 복사본에만 북마크를 추가하며, 결과 패키지에는 입력 시점의 원본 바이트를 보존합니다.

이력 파일이 전후 텍스트와 맞지 않거나 읽히지 않으면 경고를 기록하고 두 파일 비교를 계속합니다.
이력 텍스트의 일치는 서식·표 구조 또는 변경기록의 완전성을 보증하지 않습니다.
현재 이력 파일은 보조 정보로만 활용하며, 전후 파일의 비교를 생략하는 고속 경로는 적용하지 않습니다.

## 결과물

- `이름.bdsg`: ZIP 기반 분석 패키지
- `이름_변경내용_미리보기.xlsx`: 좌우 이미지, 숨김 원문 열, 상세 및 확인사항 시트
- `이름_변경전_전체.docx`, `이름_변경후_전체.docx`: 입력 원본 사본

패키지에는 `analysis.json`, 미리보기 Excel, 원본 DOCX 2개, `images/`가 들어갑니다.
JSON에는 변경 ID, 양쪽 원문, 양쪽 페이지, 블록 위치, 이미지 경로, 경고,
입력 파일 해시, 단계별 소요시간, 선택 이력의 보조 정보가 들어갑니다.
페이지는 문서의 처음부터 센 물리 페이지 번호입니다.

## 이번 버전의 비교 범위와 제한

- DOCX XML에서 **본문 문단/최상위 표 블록**을 비교합니다. 중첩표는 바깥 표와 함께 유지합니다.
- 표를 Excel 셀 구조로 재작성하지 않습니다. 변경이 있는 표 전체를 Word에서 캡처합니다.
- 목차만 제외하고 그 앞뒤의 표·문단을 비교합니다. 별첨·부록 제목을 감지하면 그 이후를 제외합니다. 포함 블록과 제외 범위는 JSON에 기록됩니다.
- 목차 또는 별첨과 검토 대상 내용이 같은 최상위 표/콘텐츠 컨트롤에 섞여 있으면 블록 전체를 제외하고 경고합니다. 원본에서 블록을 분리한 뒤 다시 분석하십시오.
- 제목·스타일·필드가 없는 불규칙한 목차나 별첨은 자동 감지가 어려울 수 있습니다. 앞부분 첨부자료 목록 판정은 목차 사이 또는 첫 목차 뒤에서 본문 제목으로 이어지는 일반 문단 형식의 번호 목록을 기준으로 합니다. 결과 범위와 원본을 확인하십시오.
- 머리말·꼬리말·각주·미주 차이는 확인사항에 기록하며 본문 이미지 비교에는 포함하지 않습니다.
- 문단 순서가 바뀌거나 문단이 분할/병합되면 문서 순서 기준으로 연결됩니다. 의미상 대응은 사람이 확인해야 합니다.
- 내용 중심 비교입니다. 자동 문단번호·수준·스타일·페이지 설정만의 변경은 제외하므로 번호나 레이아웃 검토가 필요하면 원본도 확인해야 합니다.
- 그림/개체 내부 XML은 보수적으로 비교하므로 크기·자르기 등 개체 변경도 포함될 수 있습니다. 모든 시각적 서식 차이를 제거하는 기능은 아닙니다.
- 그림 연결 대상의 내용 변경을 검사합니다. 문서의 모든 가능한 개체/외부 링크 표시 변화를 보증하는 비교 엔진은 아닙니다.
- **여러 페이지에 걸친 블록 및 캡처 실패는 텍스트로 대체**합니다. 상세 시트와 원본 Word를 확인합니다.
- 이미지 크기 변경은 원래 가로세로 비율을 유지합니다. Excel 원문 열은 제어문자 정제 및 32,767자 제한을 적용하며 전체 원문은 JSON에 보존합니다.
- 현재 결과는 변경 블록 단위 좌우 미리보기입니다. 페이지 전체 캡처나 최종 변경대비표 생성 기능은 포함하지 않습니다.
- 최종 DOCX 변경대비표는 함께 배포된 변대생기 Alpha 1.1에서 작성합니다.

## 로그와 취소

시작 즉시 **로그 열기**가 활성화됩니다. 단계별 시작/종료, 소요시간, 항목과 캡처 실패 원인을 기록합니다.
기본 위치는 `%LOCALAPPDATA%\변분기\logs`입니다.
오류창은 예외 유형·단계·짧은 내용·로그 경로만 표시합니다.
취소는 진행 중인 Word 호출이 반환된 후 적용됩니다. Word COM 호출 자체가 멈춘 경우 즉시 취소되지 않을 수 있습니다.

## 개발 및 시험

VS Code로 이 폴더를 열고 Python 코드를 수정합니다.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

`analyzer.py`: 입력 화면, 진행·로그 표시, Excel 출력

`pair_analysis.py`: DOCX 블록 비교, 선택 이력 확인, 임시 북마크

`pair_runner.py`: 이미지 추출과 패키지 생성 순서

`comparison_scope.py`: 앞부분·본문 포함, 목차·별첨 제외 범위 판정

`word_capture.py`: Word EMF 직접 추출 및 제한된 클립보드 대체

`app.py`: Alpha 0.2에서 가져온 Word 자동화/범위 감지 내부 엔진. 실행 진입점은 RUN.bat 또는 analyzer.py입니다.

자동시험은 임시 합성 문서를 사용합니다. 실제 Windows Word의 페이지 계산·클립보드 캡처는 자동시험에서 검증하지 않습니다.
Windows에서 일반 문단, 중첩표, 여러 페이지 표, 삭제/추가, 재실행 및 취소를 확인한 후 업무에 적용하십시오.
`TEST.bat`으로 Word를 열지 않는 회귀시험을 실행합니다. 실제 Word 시험은 사용자 동의 후 별도로 진행하며, 이번 결과는 `VALIDATION.md`에 기록했습니다. 한 문서의 측정값이 모든 문서의 성능을 보증하지 않습니다.

## GitHub 업로드와 배포

두 프로그램 폴더를 나란히 둔 상태에서 어느 폴더의 `UPLOAD_TO_GITHUB.bat`을 실행해도 변분기·변대생기 Alpha 1.1의 소스·시험·설명서와 통합 배포 ZIP을 함께 업로드합니다. 원격 저장소의 이력을 가져오고 작업 브랜치 `codex/alpha-1.1`을 사용합니다. Git과 GitHub 로그인 및 저장소 쓰기 권한이 필요합니다. 변경 목록을 확인하고 `UPLOAD`을 입력하면 커밋·push하며, main 반영은 Pull Request를 사용합니다.

공개 저장소에는 업무 문서, 분석 패키지, 이미지, 실행 로그 및 API 키를 올리지 않습니다. `.gitignore`에 해당 결과물과 로컬 환경을 제외했습니다. 변경 목록과 저장소 주소를 확인한 뒤 업로드하십시오.

업로드 준비만 확인하려면 `powershell -NoProfile -ExecutionPolicy Bypass -File .\UPLOAD_TO_GITHUB.ps1 -PrepareOnly`를 사용합니다. `.github-suite-preview`에 독립적인 Git 저장소, 두 프로그램 소스 폴더와 통합 ZIP을 준비하며 네트워크·커밋·push는 수행하지 않습니다. 실제 업로드 사본은 `.github-suite-upload`에 있습니다. 코드 수정은 원래 배포 폴더에서 하십시오.

통합 ZIP 재생성: `.venv\Scripts\python.exe tools\build_suite_release.py` (출력: 두 폴더의 상위 위치에 `AT_GENERATOR_Alpha_1.1.zip`). ZIP에는 `변분기_Alpha_1.1/`과 `변대생기_Alpha_1.1/` 두 폴더가 들어갑니다. 단독 ZIP은 `tools\build_release.py`로 생성합니다.

### 패키지 호환 정보

`schema_version`은 3이고 `scope_policy`는 기존 비교 정책과 동일합니다. 기존 변대생기 Alpha 1.0이 분석 패키지의 `version` 문자열을 확인하므로, 이 호환용 필드는 `변분기 Alpha 1.0`으로 유지합니다. 실제 생성기 버전은 별도 `producer_version` 필드의 `변분기 Alpha 1.1`에 기록합니다. 화면·로그·배포 파일은 Alpha 1.1로 표시됩니다.

구현 참고: [Word Range.EnhMetaFileBits](https://learn.microsoft.com/en-us/office/vba/api/word.range.enhmetafilebits), [Pillow WMF/EMF 지원](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#wmf-emf).
